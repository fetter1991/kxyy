## 临时需求登记

> **本章节独立于版本迭代记录**，用于追踪开发过程中随机加入的临时需求（可能以文字、截图、文档等形式提出）。
> 触发关键词：出现「**新增临时需求 / 新增需求 / 临时需求**」等提示时启动本流程。
> 完整流程定义见 [`Readme.md`](Readme.md)「临时需求处理流程」章节与 [`开发规范.md`](开发规范.md) 第 5 条、[`constitution.md`](constitution.md) 原则 12。

### 登记规则（强制）

1. **原文登记**：将需求提出时的原话写入本章，备注 `需求原文 · 日期YYYY-MM-DD`。
   - 图片/截图类需求：阅读图片内容后**解析为文字**再写入需求原文；不引用图片作为原文（提出后图片可能被删除）。
   - 同一天提出多条需求：合并为**一条** `需求原文`，内部用子项编号（如 1. / 2.）。
2. **解析登记**：将原文解析为符合本项目的规范说明，备注 `需求解析 · 日期YYYY-MM-DD`。
   - 解析后若与现有功能冲突，使用 **⚠️ 冲突项** 标记区分。
   - 冲突需执行时，须**先询问确认**，备注 `冲突功能解决方案 · 确认人：<git user.name> · 确认时间：YYYY-MM-DD`。
   - 确认人读取 `git config user.name`；若不可得则填占位符 `待确认`。
3. **任务拆分**：解析后的需求拆分写入 [`tasks.md`](tasks.md) 的「临时变更需求登记」区域，备注 `（新增变更需求 YYYY-MM-DD）`。

### 结构化字段模板

```markdown
#### 需求登记 #<递增序号> · <提交日期 YYYY-MM-DD>

**需求原文 · <YYYY-MM-DD>**
> 1. <原话/解析后的文字，若为图片则注明「（图片解析）」>
> 2. <多条子项>

**需求解析 · <YYYY-MM-DD>**
| 子项 | 解析为项目规范说明 | 冲突标记 |
|------|-------------------|---------|
| 1 | <功能/页面/交互的具体落点，关联 Task/原则> | ⚠️ 冲突项：<与现有功能/原则 X 冲突的具体内容> |

**冲突功能解决方案 · 确认人：<git user.name 或 待确认> · 确认时间：<YYYY-MM-DD>**

**任务拆分**：见 tasks.md「临时变更需求登记」#<序号>（新增变更需求 <YYYY-MM-DD>）
```

### v0.7.0 · 2026-08-12 · 反馈修复（滚动条统一 / 头像兜底 / 强制刷新长加载）

> **范围**：用户浏览器验收后发现 3 项偏差，本轮集中修复并验证恢复。
> **关联**：tasks.md C10（滚动条）/ C11（头像兜底，C02 增强）/ C12（强制刷新长加载，C03 增强）。

**修改项目与内容**

| 子项 | 修改内容 | 落点文件 | 验证 |
|------|----------|----------|------|
| C10 滚动条统一 | 根因：相册/个人资料/视频页滚动发生在 `html/body` 的 viewport 根滚动条，部分浏览器/系统下不接受 `*::-webkit-scrollbar` 自定义颜色，而成长历程弹窗为子容器滚动条可命中——导致全站不统一。修复：将根滚动职责下沉到 `App.vue` 的 `#app-scroll` 内部容器（`html, body { overflow: hidden }`），使全站滚动均为子容器滚动，统一命中自定义规则；滚动条样式以弹窗为基准显式绑定关键容器 | `web/src/App.vue`、`web/src/styles/original.css` | `vue-tsc -b` 0 错；`vite build` 成功；dev 截图确认相册页与成长历程弹窗滚动条均为紫灰半透明细条，视觉一致 |
| C11 头像兜底 | 根因：C02 用全局 `Set` 记录「已回退 URL」，`::key="coverUrl"` 重建 `<img>` 后同一首歌再次 error 时 URL 已在 `Set` 中被 `return`，头像停在损坏态。修复：改为 `img.dataset.fallbackApplied` 实例标记（每实例自动重置），同一实例仅回退一次，`VA.png` 自身失败直接返回防死循环 | `web/src/modules/user/components/NavPlayer.vue` | `vue-tsc -b` 0 错；`vite build` 成功；反复切换上一首/下一首/列表任意点击后头像均正确回退，无损坏态 |

**实施中关键发现**

1. **C10 根滚动条无法自定义（核心难点）**：初版仅在 `original.css` 给 `html/body` 加显式 `::-webkit-scrollbar` 规则，验证发现根滚动条仍走系统默认（灰），通配符与显式规则均无法覆盖 viewport 根滚动条。最终确定「根滚动职责下沉内部容器」方案——所有页面滚动发生在 `#app-scroll`，其作为子容器可被 `*::-webkit-scrollbar` 自定义。排查确认项目无 `window.scrollY/scrollTo` 依赖（仅 GrowthView 用 `el.scrollTop` 内部元素），下沉不破坏既有逻辑。
2. **C11 防死循环标志归属**：原 C02 用 `Set` 防死循环正确，但标志"生命周期"应绑定当前 `<img>` 实例而非永久 URL——切歌重建节点后旧标志应失效。改为 `dataset` 实例标记即契合 Vue 的 `:key` 重建语义。
3. **C12 遮罩语义修正**：遮罩职责是"等待数据就绪"而非"固定表演时长"。改为数据驱动收起后，首屏体验与接口速度解耦，长加载问题消除。

**测试结果**：⏳ → ✅ 三项均通过类型检查 + 构建 + dev 运行时截图验证（滚动条视觉一致、头像回退正常、遮罩随数据消失）。
